# AI Emby

AI Emby 是一款电影、剧集与 STRM 媒体库管理服务。在一个面板里完成媒体浏览、文件管理、扫库和元数据刮削，适合管理本地磁盘、NAS 或挂载目录中的影视资源。

## 主要功能

- **媒体库管理**：管理电影与剧集，支持全量扫描、刷新扫描、定时扫描和媒体库排序。
- **网页大屏播放**：选集后铺满页面观看，支持倍速、进度跳转、音量、全屏、画中画、播放中选集、上一集 / 下一集和自动连播；保留断点续播、播放版本及字幕、音轨、章节等控制。
- **并发扫库**：同时处理多个媒体库，也可调整单个媒体库内的文件扫描并发。
- **网盘挂载与 STRM**：直接挂载移动云盘、115、夸克、光鸭和 WebDAV，在面板浏览目录并批量生成 STRM；可选择直链 302 或服务器中转，WebDAV 使用服务器中转。
- **追新索引**：接入 PanSou，直接搜索电影或剧集，无需先订阅；支持按年份、网盘和来源搜索，复制分享链接或选择资源入库、生成 STRM、刮削与标准命名。也可订阅作品并定时追新，集中管理未读资源和自动入库。
- **资源搬运**：从搜索结果转存、下载视频，使用 FFmpeg 无损重封装后上传到移动云盘或多个网盘；保留转存盘原文件，支持暂停、恢复和失败重试。
- **规范命名**：自动搜索 TMDB，结合标题、年份和作品类型匹配并批量标准命名，支持手动预览、正则替换和顺序编号，关联字幕、NFO、缩略图随同改名。
- **元数据刮削**：通过 TMDB 获取 NFO、海报、背景图和剧集缩略图，支持选择目录、磁盘及刮削并发。
- **自动处理**：监控媒体目录变化，按设置自动刮削或刷新本地元数据。
- **任务中心**：查看任务历史、运行状态、阶段记录与失败原因，重新执行扫描和资料补全任务。
- **每库设置**：独立设置文件并发、默认排序、用户访问范围，以及扫描后的资料补全、媒体信息提取和缺图截帧。
- **作品管理**：编辑资料、确认 TMDB 匹配、上传或选择海报和背景图；可选择是否写回媒体目录。
- **浏览与整理**：按年份、类型、地区、标签和评分筛选作品，建立个人或共享合集。
- **播放管理**：查看观看记录、设置音轨和字幕偏好，使用浏览器转码、弹幕、章节跳转和封面截帧。
- **文件与账号管理**：添加和切换多个本地目录，支持只读路径与文件操作；管理用户、播放权限、登录设备和 API 密钥，支持注销指定设备。
- **日常使用**：浅蓝白管理面板、明暗主题切换、当前设备保持登录，并提供字幕增强、片头片尾和 Telegram 通知等设置。

## 资源搬运与无损处理

1. 在「追新索引」搜索资源，点击搜索结果中的「下载处理」。
2. 选择与分享同平台的转存账号和目录，例如夸克分享选择夸克账号，115 分享选择 115 Cookie 账号。
3. 选择处理后的上传网盘和目录；默认选择已挂载的移动云盘，也可同时选择多个网盘。
4. 选择 MKV 或 MP4，设置本次视频数量、文件并发和临时空间上限，开始任务。
5. 在「资源搬运」查看每个文件的转存、下载、重封装和上传进度。暂停或失败后可继续，并可调整并发和临时空间上限。

无损处理使用 FFmpeg 复制原有音视频流，不重新编码。默认 MKV，保留音轨、字幕、附件和章节；所选封装不支持源文件的流时停止处理，保留下载副本。处理后会检查编码、流数量、章节和时长，检查通过后才上传。重封装会改变文件容器结构，处理速度取决于服务器磁盘读写速度。

原始视频保留在转存盘。每个任务建立独立目录，保留分享内的子目录结构。所有上传目标确认文件大小后才清理临时文件，也可选择保留本地文件。下载和上传会使用服务器流量，长传输不设总时长限制，网络持续无响应约三分钟时暂停该文件并允许重试。

服务重启后未完成的运行任务变为暂停，在「资源搬运」中继续；已确认上传的目标会跳过。取消任务保留网盘文件和未完成的本地副本。临时文件位于应用数据卷的 `features/cloud-transfers` 目录；保留本地文件时需自行管理占用空间。

分享转存支持情况与追新入库一致。115 开放平台账号可以作为上传目标，分享转存需使用 115 Cookie 账号。上传能力取决于网盘驱动、账号权限和剩余空间；只读挂载不能上传。Docker 镜像内已包含 FFmpeg 和 FFprobe。

## 安装

### 环境要求

- Linux x86_64（amd64），或 Windows 的 Docker Desktop（Linux 容器）。
- 已安装 Docker、Docker Compose 和 Git。
- 可访问的媒体目录；需要写入 NFO 和图片时，该目录应可写。

数据库由 Docker Compose 一并启动，无需单独安装 PostgreSQL。

### 1. 准备部署目录

```bash
git clone https://github.com/LLL198/ai-emby.git
cd ai-emby
cp .env.example .env
mkdir -p app-backups secrets media update-control
```

### 2. 填写配置

用文本编辑器打开 `.env`，填写数据库密码、管理员初始密码和媒体目录。

| 配置项 | 用途 |
| --- | --- |
| `POSTGRES_PASSWORD` | 必填，数据库密码 |
| `ADMIN_PASSWORD` | 必填，首次创建管理员的密码，至少 12 字节；使用英文字符时至少 12 位 |
| `MEDIA_PATH` | 宿主机媒体目录，例如 `/mnt/media`；默认 `./media` |
| `HTTP_PORT` | 网页访问端口，默认 `8097` |
| `IMAGE_TAG` | 镜像版本，默认 `latest` |
| `PUID` / `PGID` | 容器运行用户和用户组，默认均为 `0`；自定义时需确保媒体与数据目录可读写 |

已有账号的密码请在面板内修改，调整 `ADMIN_PASSWORD` 不会重设已有管理员密码。

### 3. 启动服务

```bash
docker compose pull
docker compose up -d --no-build
```

浏览器打开 `http://服务器地址:8097`。如果修改了 `HTTP_PORT`，使用对应端口。

首次登录使用用户名 `admin`，密码为 `.env` 中填写的 `ADMIN_PASSWORD`。

登录后会自动记住当前设备。清除网站数据、退出登录或修改密码后，需要重新登录。

## 挂载网盘与生成 STRM

1. 打开「内容管理 → 网盘挂载」，点击「添加网盘」。
2. 选择网盘并填写账号配置，保存后查看连接状态。
3. 点击挂载卡片进入目录，找到电影或剧集所在目录，点击「生成 STRM」。
4. 选择 `/media` 内的输出目录，填写播放设备能够访问的 AI Emby 服务地址。
5. 设置是否包含子目录、数量限制和文件写入并发；可选择完成后扫描已有媒体库。

| 网盘 | 登录方式 |
| --- | --- |
| 移动云盘 | Authorization；高级配置也支持移动邮箱 Cookie 和账号登录 |
| 115 | 已登录账号的 Cookie，或选择 115 开放平台填写 Access Token / Refresh Token |
| 夸克 | Cookie；302 播放可补充自己账号的移动端请求 URL，原码播放可选择服务器中转 |
| 光鸭 | Client ID 与 Token；也支持填写手机号码，发送短信后再次编辑填写验证码 |
| WebDAV | WebDAV 服务地址、账号、密码和根目录路径；高级配置可选择通用服务或 SharePoint |

WebDAV 地址填写完整的服务入口，例如 `https://dav.example.com/dav/`，根目录填写 `/` 或入口下的子目录（例如 `/电影`）。服务地址需要能从 AI Emby 所在服务器或容器访问；Windows Docker 中连接宿主机服务时，可使用 `host.docker.internal` 作为主机名。HTTPS 服务需使用受信任的证书。账号和密码单独填写，编辑时留空保留已保存的认证信息。WebDAV 使用服务器中转读取，支持 Range 请求、播放拖动和 HEAD 探测，视频流量经过 AI Emby；生成的 STRM 不包含 WebDAV 账号密码。

STRM 保留目录结构，例如 `电影/示例.mkv` 生成 `电影/示例.mkv.strm`。文件里存放签名的 AI Emby 地址，网盘 Cookie 和临时下载地址不会写入 STRM。暂停或删除挂载会停用相应播放链接，重新启用原挂载后链接可继续使用。

数量限制为 `0` 时不设用户数量上限；单次安全上限为 10 万个视频，可按目录分批生成。写入并发为 1–8，与刮削并发分开设置。任务支持取消，已生成文件会保留，再次生成默认跳过已有文件。

输出目录尚未建库时，可先生成文件，再到「媒体库」添加该目录。生成任务和失败原因可在网盘页及「任务中心」查看。

挂载配置中可以选择播放方式。直链 302 的视频流量由播放器直接向网盘读取，目录请求、直链解析及媒体资料仍经过服务器；服务器中转由 AI Emby 携带网盘认证读取视频，会消耗服务器流量。切换播放方式后，已有 STRM 继续使用，无需重新生成。服务不会自动把 302 回退到中转。

「播放管理 → 防盗保护」提供独立的播放链接保护开关，默认开启。新安装或旧配置未保存此开关时会自动启用；已经明确保存的关闭设置会保留，仍可手动关闭。开启后，本服务生成的网盘 STRM 只能通过登录后的 AI Emby 播放入口观看；直接请求 STRM 中的长期签名解析地址会被拒绝。服务端在播放入口检查登录、媒体库访问权限、播放权限和设备上限后完成解析，不再向播放器发送长期 STRM 地址。已有 STRM 无需重新生成，关闭开关恢复原有访问方式。扫库、媒体探测、封面截取、字幕提取和转码使用私有工作端口上的限时凭据，不受外部解析限制影响。此开关不保护外部服务生成的 STRM。

普通用户的作品详情、媒体列表和 GET / POST PlaybackInfo 均返回带登录校验的播放入口，不返回 STRM 原地址；内网访问或缺少播放器请求头也不会改变此规则。专用服务 API 的取源能力保留。使用 302 直连时，实际播放仍会跳转到网盘临时地址，播放器和抓包工具可能看到跳转后的地址。

防盗保护还提供账号播放请求频率限制，默认关闭，预设上限为每账号每分钟 60 次。按任意连续 60 秒统计外部 GET / HEAD 播放入口，同账号的不同设备、令牌和网关进程共享计数；海报、扫库、PlaybackInfo、进度上报和私有媒体任务不计数。支持全局上限和单账号上限（留空继承全局，0 表示该账号不限次数），超限处理可选仅警告、临时封禁或永久封禁。警告允许继续播放，同账号每分钟最多记录一次；临时封禁可设 1–43200 分钟，到期自动恢复；永久封禁需管理员在模块中解除。封禁会拦截后续登录和账号请求，释放该账号的播放名额，并在数据库中持久保存。已建立的中转连接、已获取的网盘直链不会被主动断开。关闭限频或修改上限不自动解除已有封禁。管理员免于自动限频和封禁，保留恢复入口。记录保存最近 1000 条，页面展示最近 100 条。

登录令牌参数不区分大小写；同一参数重复出现且值不同时，会拒绝该请求，避免登录校验和限频计数识别出不同账号。重复且相同的令牌仍可正常使用。

保护模式兼容直链 302 和服务器中转。302 发出的最终网盘直链仍可能在网盘允许的有效期内被复用；需要隐藏最终视频源时请选择服务器中转。退出登录、禁播或修改权限会在后续播放请求中检查；已经建立的视频传输不会被此开关主动断开。

115 的直链绑定客户端 User-Agent。夸克出现 `plf_invalid` 时，编辑夸克挂载，在「移动端请求 URL」中填写手机登录同一账号后获取的 `https://drive-m.quark.cn/1/clouddrive/…` 完整请求地址，需包含 `kps`、`sign`、`vcode`、`ut` 参数。保存后继续使用已有 STRM，无需重新生成。此字段留空会保留已保存凭据；凭据过期时需要重新获取并替换。实际直链可用性取决于夸克返回结果和账号的视频播放权限。

网盘账号及播放凭据保存在应用的数据卷内，Docker 内已集成驱动引擎，无需另外部署网盘服务。组件的对应源码和许可见网盘页面底部「网盘组件许可与源码」。

## 追新索引与盘搜

打开「内容管理 → 追新索引」，配置 PanSou 服务后，在「搜索资源」输入作品名称直接搜索，也可添加电影或剧集订阅定时追新。默认只列出分享资源。需要自动入库时，在订阅中勾选「自动入库」，自行选择网盘账号、转存父目录、STRM 父目录和媒体库，并填写播放器可访问的 AI Emby 地址。

资源卡片的「解析链接」可以统计分享及子文件夹中的视频数量，显示 MKV、MP4、ISO 等格式的数量，并保留最近一次解析时间。图片、字幕和文档不计入视频数量；解析只读取目录，不转存或下载视频。同类网盘只挂载一个账号时直接开始解析，有多个账号时可自行选择。支持移动个人云、115 Cookie、夸克和光鸭分享，可点击「重新解析」刷新数量。

使用随 Compose 提供的可选 PanSou 服务：

```bash
docker compose --profile pansou up -d pansou
```

在「盘搜设置」填写 `http://pansou:8888`，保存后点击「检查已保存的连接」。该服务只开放容器网络内的接口。也可以接入已有的 PanSou 服务，填写容器能够访问的 API 地址；Windows Docker 访问宿主机服务时使用 `http://host.docker.internal:8888`。启用认证的服务可以配置账号密码，或填写 Bearer Token；密码和 Token 编辑时留空保留，变更服务地址会清除旧服务凭据。

- 添加订阅时填写名称、年份、搜索间隔和目标网盘，搜索关键词留空时使用名称与年份。可填写独立关键词，并用包含词和排除词筛选；多词使用逗号分隔，包含词满足任意一个即可。
- 每个订阅可独立暂停。开启「启用定时追新」后，按各自周期搜索；也可点击「立即搜索」或「搜索全部」。默认间隔 6 小时，最短 15 分钟。
- 相同分享链接去重；资源说明或提取码变化会重新标为未读，已忽略的资源继续保持忽略。提供全选本页、批量已读、批量忽略及分页。
- 关联媒体库中的整部剧集可显示已有季、集数和最大集编号。搜索返回的是分享资源说明，需自行确认年份、版本和实际集数；分享链接是否有效以网盘实际返回为准。
- 首次索引最多接收每次搜索的 1000 条分享链接。PanSou 的插件可能在后台继续搜集结果，首次无结果时可稍后再次搜索。

自动入库支持夸克、115 Cookie 挂载、移动个人云（personal_new）和光鸭。系统按名称和年份选择同类型网盘的分享，并沿用该分享追踪后续更新；也可以在资源列表点击「使用此资源入库」固定分享。

识别作品时结合订阅名称和搜索结果中的年份，文件名提供季集编号。即使文件用了英文名或其他名称，也会沿用入库时确认的作品信息进行刮削。包含「更新至某集」等信息的分享会推荐剧集库；电影和剧集选错媒体库时会提示调整。

在「盘搜设置 → 入库默认处理」选择「自动刮削」和「自动重命名」，订阅和单次资源入库也可分别调整。自动刮削需开启刮削总开关；自动重命名需配置 TMDB，结合订阅名称、年份及文件季集号规范本地 STRM，并迁移对应的 NFO、图片和观看记录。网盘原视频保持原名，后续追新沿用已有 STRM，不重复生成。无法确认的命名或重名冲突会保留原名，集中显示在刮削模块的「待处理」。默认开启自动刮削，自动重命名由你选择开启。

已有同名同大小的视频会跳过，默认每次最多转存 200 个新视频，数量可自行调整。网盘与本地父目录下会建立作品目录。网盘转存通过服务端接口完成，视频内容不会下载到 AI Emby；播放方式沿用目标挂载的设置。

转存、STRM、扫库、刮削的进度和失败原因可在订阅、任务中心与日志查看；失败后可点击「重试入库」。网盘异步任务会保留记录，下次执行继续确认结果。关闭自动入库时仍可手动转存，并在「网盘挂载」生成 STRM。

PanSou 项目：<https://github.com/fish2018/pansou>。搜索来源取决于所连接服务启用的插件与频道；可在 Compose 的 PanSou 环境配置中调整。

## 文件管理与本地路径

打开「文件管理」，在顶部切换目录，点击「添加路径」输入名称和本地目录，或使用「选择目录」浏览。支持浏览、搜索、上传、下载、新建文件夹、移动、删除和文件夹改名。路径可以设为只读；在「管理路径」移除入口不会删除磁盘文件。路径配置会保留，刷新页面或重启后仍可选择。

Linux 服务可直接添加有权限访问的绝对目录，例如 `/mnt/videos`。在 Docker 中，先挂载额外目录，再填写容器内路径，例如：

```yaml
# 在 ai-emby 服务的 volumes 中增加
- /mnt/videos:/movies:rw
```

Windows Docker Desktop 可挂载 Windows 目录。在直接由 Windows 执行的 Compose 中使用：

```yaml
# 在 ai-emby 服务的 volumes 中增加
- "E:/123/openlist:/local/openlist:rw"
```

如果从 WSL 执行 Compose，对应宿主路径写成 `/mnt/e/123/openlist`。重建容器后，在面板添加 `/local/openlist` 即可。

想在面板输入和复制 Windows 原始路径，可在 `.env` 配置映射，并使用同一个容器挂载点：

```dotenv
FILE_MANAGER_PATH_MAPPINGS='[{"host":"E:\\123\\openlist","container":"/local/openlist"}]'
```

映射只负责转换路径，实际挂载仍需在 Compose 中配置。Linux Docker 也可使用同样的映射格式。面板访问的是运行 AI Emby 的服务器目录，不能直接访问其他客户端电脑的磁盘。新增路径不会自动建立媒体库；需要扫库和刮削时，在媒体库设置中添加对应容器目录。

## 添加媒体库

1. 打开管理面板的「媒体库管理」，选择「新建媒体库」。
2. 填写名称，选择电影或剧集类型。
3. 选择容器内的媒体目录，保存并查看扫描进度。
4. 在「每库设置」选择自动处理内容、默认排序和访问用户。

`MEDIA_PATH` 指向的宿主机目录在容器里显示为 `/media`。例如，宿主机 `/mnt/media/电影` 对应面板中的 `/media/电影`。

电影和剧集建议分别建库，剧集按季整理。可参考以下命名：

```text
/media
├── 电影
│   └── 电影名称 (2024)
│       └── 电影名称 (2024).strm
└── 剧集
    └── 剧集名称 (2024)
        └── Season 01
            ├── 剧集名称.S01E01.strm
            └── 剧集名称.S01E02.strm
```

剧集文件名保留 `S01E01` 这样的季集编号，有助于识别具体集数。存在同名作品时，可在作品目录名中加入正确的 `{tmdb-编号}`，例如 `电影名称 (2024) {tmdb-12345}`；示例编号需替换为实际作品的 TMDB ID。

没有季目录的剧集会按单集的季号自动显示季入口。同一作品合并多个片源时，季目录中的单集和作品目录下的同季单集合并到一个季入口，优先沿用已有季目录的封面和名称；相同单集保留可切换的播放版本，缺少的集数一并补入。这个分组只影响浏览，不移动原文件。旧的虚拟季链接仍可访问，媒体库可见权限和版本合并开关继续生效。

## 规范命名

打开「刮削管理 → 手动任务」，在「选择目录 / 磁盘」里设置范围，然后选择「仅规范命名」或「规范命名后刮削」。命名与刮削共用目录选择和子目录排除规则，默认整理媒体文件、作品和季目录，以及关联字幕、NFO 和缩略图。取消「同时规范作品和季目录」可只整理文件；分类、多作品目录、媒体库根目录及包含已排除子目录的父目录保持原名。父子目录可一起改名；目标名称已存在或多个项目的名称重叠时，正常跳过这些项目并继续处理其他内容，不计为命名失败，也不加入待处理列表。

选择「规范命名后刮削」并点击「命名并刮削」，会依次完成匹配、改名、媒体库刷新和元数据刮削。目录改名后，选择规则会同步更新。高级命名规则里可调整类型、标题、年份和模板。后续步骤由当前页面衔接，请保持页面打开；停止任务或离开页面会停止启动后续步骤，已完成的改名保留，已经启动的扫描或刮削由任务中心管理。

「刮削管理 → 待处理」集中显示无法确定作品或集号、命名冲突和刮削失败的项目。列表保存完整路径、原因和最近发现时间，支持搜索、按来源和问题类型筛选。点击「修正命名」可补充作品名、年份、季号或选择 TMDB 作品后预览改名；刮削失败项目可单独重试，也可勾选或全选本页后点击「批量重新刮削」，查看计划并开始一个批量任务，沿用当前刮削内容、并发和覆盖设置。混合选择时只重刮元数据刮削来源的项目，命名问题需先修正。成功处理后自动移出列表，仍失败的保留原因。暂时不处理的项目可以忽略，并在「已忽略」里恢复；目录改名后记录路径同步更新。列表从启用此功能后的命名扫描和刮削任务开始积累，刷新页面或重启服务后仍会保留。

扫描、TMDB 匹配和改名都有实时进度，结果按相对路径显示，避免不同季目录的同名文件混淆。一次可扫描最多 100000 个媒体项目、500000 个目录项，超过范围会提示缩小选择，本次不会改动文件。结果列表分批显示，但自动命名会处理全部可改名项目。

| 命名方式 | 适用情况 |
| --- | --- |
| 自动标准命名 | 自动搜索 TMDB 并匹配作品；识别 `S1E2`、`1x02`、`第一季第二集`、`EP02`、`第十二集` 等季集编号 |
| 正则替换 | 删除固定发布标签、替换前后缀等有规律的名称；文件扩展名自动保留 |
| 单季顺序编号 | 在高级命名规则里打开；选择具体季目录，指定作品、季号和起始集号后，按名称自然排序编号 |

默认勾选「自动搜索 TMDB」，点击「自动命名」即可完成匹配和改名，无需逐个选择作品或再次确认。系统结合标题相似度、年份和电影/剧集类型选择匹配：名称存在少量差异也可以匹配；已有 TMDB 编号时直接读取作品资料。同一部剧的多集共用匹配结果，已符合标准的名称保持不变。多个候选匹配接近、类型或季集冲突、目标重名时跳过，完成后显示原因。

电影名称中的数字会保留，避免把续集当作其他作品；同名电影目录中的年份和 TMDB 编号可供文件命名及刮削共同使用。电影 NFO 的年份优先采用 TMDB 确认的上映日期。

剧集推荐格式为 `作品名称 (年份) - S01E02 - 分集标题 {tmdb-编号}.mkv.strm`，电影为 `作品名称 (年份) {tmdb-编号}.strm`，季目录为 `Season 01`。作品名称、发行年份和编号来自 TMDB，季集编号来自本地文件，分集标题保留原文件名中的内容。可以填写名称、年份和类型帮助匹配，或使用「手动选作品」指定 TMDB 候选；取消自动搜索则只按本地信息整理。

模板支持 `{title}`、`{title_original}`、`{year}`、`{season:2}`、`{episode:2}`、`{episode_name}`、`{quality}`、`{tmdbid}`；文件扩展名自动保留。原名来自匹配的 TMDB 作品，分集标题取自已有文件名。

`01.strm` 这类裸集号需要勾选确认，并提供季目录或季号。动漫绝对集数、合集、多集文件和特别篇需人工核对，系统不会自动猜测它们对应的 TMDB 季集。顺序编号适用于已确认分集顺序的文件，需要进入具体季目录操作，不会跨子目录重排集号。

需要手动检查时，点击「生成预览」，检查旧名、新名和关联文件，再执行选中的可改名项目。正则替换与单季顺序编号使用这个流程。冲突名称不会覆盖；同名字幕、NFO 和缩略图随同改名，STRM 内容中的播放链接保持不变。改名同时迁移已有作品、收藏和观看进度，随后刷新相关媒体库。

执行前结束媒体库扫描和刮削，并关闭实时刮削监控。递归改名从最深层开始：先改文件，再改季目录，最后改作品目录，收藏、观看记录和资料路径随之迁移。扫描和匹配阶段可停止准备工作，已开始执行的改名会继续完成。改名记录保存在应用数据目录的 `rename-history` 文件夹，可用于排查或恢复；预览保留一小时，服务重启后需要重新生成。

## 扫库与刷新

在媒体库菜单中选择「全量扫描」或「刷新扫描」，也可以使用「刷新全部媒体库」。任务进度与失败原因可在「实时日志」中查看，运行中的任务支持暂停和继续。

「扫描与定时设置」中可以调整：

| 设置 | 作用 | 范围 |
| --- | --- | --- |
| 同时扫描上限 | 同时进行全量扫描的媒体库数量 | 1–64 |
| 同时更新上限 | 同时进行刷新扫描的媒体库数量 | 1–64 |
| 单库扫描并发 | 单个媒体库内同时处理的文件数量 | 1–32，默认 8 |

并发设置对新任务生效。机械硬盘、网络挂载或繁忙的 NAS 建议逐步增加并发，结合实际速度与磁盘负载调整。

需要自动扫库时，可设置每日、每周或按分钟间隔执行。面板中的定时时间使用 UTC。

## 元数据刮削

扫库负责把媒体加入影库；刮削负责获取作品信息，并将所选 NFO 和图片写入媒体目录。

### 配置 TMDB

打开「TMDB 管理」，填写 `API Key / Read Access Token`，确认 API 基础地址与请求频率，然后保存。通过代理访问时，在「代理设置」中启用相应范围。

需要浏览时自动获取信息，可开启「启用 TMDB 按需元数据」。

### 手动刮削

1. 打开「刮削管理」，开启「启用刮削」。在「刮削配置」中启用 TMDB，点击「配置刮削内容」选择电影、剧集、季和单集需要下载的内容。
2. 设置覆盖策略：可跳过已有文件，也可覆盖已有文件；中文元数据、中文海报和 Fanart.tv 按需配置。
3. 在「实时监控」中关闭监控，再进入「手动任务」。
4. 点击「选择目录 / 磁盘」，勾选本次处理的范围。
5. 点击「刮削并发」，设置同时处理的媒体数量，支持 **1–32**。
6. 点击「扫描任务」，查看待刮削、跳过和覆盖的文件，再点击「开始刮削」。

修改范围、并发或刮削配置后，需要重新扫描生成任务计划。刮削并发与 TMDB 请求频率分别设置，提高并发仍会受到 API 请求频率限制。

图片下载另外限制为最多 6 项同时处理，排队不会消耗单项下载时限；临时网络错误、超时、HTTP 429 和 5xx 最多尝试 3 次，取消任务会停止后续重试。无效图片、HTTP 403/404 等错误不重复请求。部分目标下载失败时，已成功写入的 NFO 和图片会保留，待处理列表会明确显示「部分刮削失败」。

刮削过程中可查看逐项日志，暂停、继续或停止任务。失败记录会显示具体媒体、目标文件和原因，修正后可重新选择相关目录刮削。

### 实时监控

在「刮削管理 → 实时监控」选择媒体库目录并启用监控，可自动处理新增或变化的内容，也可开启「自动刷新本地元数据」。执行手动批量刮削前，先关闭实时监控。

## 资料编辑与重新识别

在作品详情或作品菜单中打开「编辑媒体资料」「重新识别」或「管理图片」。重新识别支持按标题搜索和直接输入 TMDB ID，确认候选后保存。单集使用所属剧集的匹配，需要修正剧集时先重新识别剧集。

资料补全默认保存在应用中。勾选「同时写入 NFO」或在每库设置中启用写回，才会写入媒体目录。已有 NFO 中未编辑的扩展字段会保留。使用「恢复本地 NFO 资料」可以清除应用保存的该作品资料，并重新扫描所在媒体库。

图片可以从本地上传，也可以在 TMDB 图片候选中选择。应用会保留作品资料与图片缓存，重新建库时可通过补全任务复用。

## 任务与定时

「任务中心」提供全部、运行中、失败与中断筛选，以及阶段记录和任务时长。扫描、刷新和每库处理任务会保存历史；服务重启后未完成的记录会标记为中断。

「定时任务」可以选择每日、每周或按分钟执行，并选择参与任务的媒体库。启用播放期间推迟执行后，会在播放结束或达到推迟上限时执行；「立即执行」直接加入队列。启用新定时任务后，原有定时扫描会关闭，避免重复执行。

## 发现与合集

影库顶部的「发现」支持媒体库、电影/剧集、年份、类型、地区和标签筛选，并可按添加时间、名称、年份、评分或首映日期排序。类型、地区和标签来自已有作品资料。

在「合集」创建合集，再通过作品菜单添加内容。合集可以仅自己查看，也可以共享给其他用户；用户仍只能访问获准查看的媒体库。

## 播放、弹幕与缓存

- 在账户菜单的「播放偏好」设置优先音轨语言、字幕语言和默认弹幕开关。
- 「播放与记录」中可启用浏览器转码，并设置编码线程、同时转码任务和视频码率。转码使用 CPU，不包含硬件加速配置。
- 播放器提供音轨、字幕、转码、章节和管理员截帧操作。文字字幕可转换为 WebVTT；图像字幕需要兼容播放器。
- 弹幕支持上传本地 XML，以及配置返回 XML 的远程地址模板；不包含特定弹幕服务的账号登录或搜索接口。
- 每库的片头片尾任务读取媒体自带章节，并在播放器提供章节跳转和片头跳过；没有对应章节的文件可继续使用原有播放行为学习设置。
- 「缓存管理」显示播放缓存大小、任务状态与实际处理方式，支持暂停、继续、停止以及删除任务和缓存。手动删除会先停止媒体工具，再清除对应文件；自动容量清理仍保护正在生成或使用的缓存。
- 网页播放器提供后台任务控制，暂停视频会暂停对应任务并保留处理进度。退出或结束播放会停止并删除任务及对应缓存，再次打开时重新生成播放输出，观看进度仍正常保存。直接关闭标签页时也会尝试删除；后台超过 5 分钟收不到播放任务心跳，会停止并删除遗留任务，包括已完成的任务。历史遗留缓存仍按保留天数和容量设置清理。

本地扫描支持 STRM、MKV、MP4、MOV、AVI、WebM、TS、M2TS 和 ISO 等文件。网页播放 ISO 时会先读取文件头识别实际格式：改后缀的 MKV、MP4 等视频优先直接播放，启用浏览器转码后可在解码失败或只有声音时自动转换。

真正的光盘镜像需要开启「播放与记录 → 浏览器转码」。本地镜像按需读取内部正片；远程镜像优先通过 HTTP Range 读取，边读边封装或转码，无需先下载整张 ISO。支持 DVD 连续 VOB、镜像内普通视频和蓝光播放列表。带索引或 CLPI 导航的原生蓝光交给新增的 libbluray 读盘组件，通过分段回调直接读取镜像，处理正片选择、默认角度和片段导航；已验证 UDF 2.50、双片段和多角度样本。简化的线性蓝光仍可使用原有读取路径，无关的短菜单或静态画面列表不再阻断正片。目录探测使用小分段，正片读取使用 4 MiB 分段，每个任务的源数据块缓存最多 8 MiB；本地读取也复用该缓存。网页兼容的 8 位 H.264 在从头播放时保留视频编码，其余情况转换为浏览器可播放的格式。

网页转码现在直接发送实时 MP4 片段，输出队列最多 512 KiB，不再把转码视频写成磁盘文件。拖拽、快进快退、章节和跳过片头会停止旧任务，从目标时间按需读取并重新生成片段，可以跳到尚未转码的位置，也能回到当前起点之前；连续拖动保留最后一次目标。软件转码保留比例，最高输出 1920×1080，减少 4K HEVC 的网页播放等待；从头封装兼容 H.264 时保留原视频。片尾续播自动从头开始，只有包含实际媒体片段的输出才视为可播放。旧客户端不请求实时输出时仍兼容原来的磁盘播放缓存。

网盘源不支持可靠的分段读取，或镜像无法由按需读盘组件处理时，会回退到完整缓存，页面显示下载进度。Docker 源码构建和更新包构建均包含读盘组件及运行依赖；自行运行二进制时还需安装 FFmpeg、7z / 7zz，并按 [读盘组件说明](disc-reader/README.md) 构建 `ai-emby-disc-reader`。支持的按需路径只保留小型任务记录，不缓存源 ISO、提取正片或播放输出；完整缓存回退仍需留出镜像和提取正片空间。跳转耗时取决于网盘分段读取和 CPU 转码速度。不包含加密光盘解密与完整光盘菜单。验证范围和限制见 [ISO 排查记录](docs/iso-playback-investigation.md)。

## 导入与访问设置

「资料导入」可以连接 Emby 或 Jellyfin，读取来源媒体库和用户，再将来源路径映射到本机挂载目录。可导入作品资料、媒体信息、章节，以及用户进度和收藏。来源进度较新时才覆盖本地进度，已有本地收藏会保留；媒体文件需要事先挂载到本机。

「访问与网络」可设置用于分享作品的外部访问地址、允许的访问主机和跨域来源。分享作品仍需登录并具有相应媒体库的权限。「登录设备」可重命名设备或注销指定设备。

## 系统更新

需要在面板中安装更新时，先为部署主机安装更新服务。主机需支持 systemd，并安装 Python 3.11+、curl 和 Docker Compose。

在部署目录执行一次：

```bash
sudo bash scripts/install-updater.sh "$PWD"
```

随后打开「系统设置 → 检测更新」，按页面提示安装。更新期间服务会短暂重启，完成后重新打开页面即可。

使用自定义 `PUID` / `PGID` 时，安装后确认对应容器用户能读写 `update-control` 目录。更新日志与数据库备份保存在 `app-backups/updates/`。

每次更新会并行备份数据库与应用数据。新版本通过健康检查和版本校验后，自动删除下载包与解压目录，自动更新生成的恢复备份只保留最新一份；日志保留，手动备份不受影响。更新失败时保留当次文件和原有备份供恢复。已安装的宿主机更新服务需使用最新源码重新执行上述安装命令，安装脚本会重启更新服务使清理规则生效；安装前确认没有正在执行的更新。

## 数据保存与日常维护

| 存储位置 | 内容 |
| --- | --- |
| Docker 卷 `app-data` | 应用数据、网盘登录信息与缓存 |
| Docker 卷 `postgres-data` | 账号、媒体库、网盘配置与追新订阅 |
| `app-backups/` | 备份与更新日志 |
| `update-control/` | 面板更新服务使用的目录 |
| `MEDIA_PATH` 指定的目录 | 媒体文件、STRM，以及刮削生成的 NFO 和图片 |

新安装使用 Docker 持久卷保存数据库和应用数据，卷名带有 Compose 项目名前缀。重启电脑、Docker 或容器不会清空这些数据。备份仍保存在部署目录的 `app-backups/`；迁移设备时，数据库和应用数据需要一起备份和恢复。

日常停止服务使用 `docker compose stop`。不要使用 `docker compose down -v` 或删除数据卷；这些操作会删除新安装的持久数据。

旧安装如果仍使用 `./postgres-data`、`./app-data` 目录挂载，**先保留原来的 Compose 文件执行迁移，再换用新版配置**。直接换成空的持久卷，会看起来像丢失数据。在 Windows 的 WSL 部署中，Docker 可能早于 WSL 磁盘挂载启动，因此更推荐使用持久卷。

在原服务正常运行时，用本仓库中的脚本指定原部署目录：

```bash
python3 scripts/migrate-storage.py --project /原部署目录
```

脚本会暂时停止应用，备份数据库与应用数据，将数据恢复到新卷，再启动服务。原目录及备份均会保留。使用自动更新服务时，先暂停更新服务，迁移结束后再启动。数据已经丢失时，请先从有效备份恢复，再迁移；迁移空数据库不会找回历史数据。

查看服务状态和日志：

```bash
docker compose ps
docker compose logs -f --tail=100
```

停止或重新启动：

```bash
docker compose stop
docker compose up -d --no-build
```

迁移已有部署时，保留 `.env`、应用数据、数据库和媒体挂载路径，并沿用原来的 Compose 项目名与服务名。

## 常见问题

**面板看不到媒体目录**

检查 `MEDIA_PATH` 是否指向正确的宿主机目录，面板中选择的路径是否位于 `/media` 下，以及容器用户是否有读取权限。

**刮削识别失败**

先查看日志中的标题、年份和媒体类型，再检查媒体库类型、目录名及季集编号。同名或容易混淆的作品可以补充正确的 TMDB ID。

**NFO 或图片写入失败**

检查媒体挂载是否可写、容器用户是否有写入权限，以及网络挂载或云盘文件系统是否支持所需写入操作。具体错误路径以日志为准。

**提高并发后仍然很慢**

查看磁盘、网络与 TMDB 请求频率。多个并发设置会共同影响负载，可先减小任务范围，再逐步调整。

**面板检测到更新，但无法安装**

确认宿主机更新服务已安装并运行，容器能读写 `update-control`，再查看面板提示及 `app-backups/updates/` 中的更新日志。

## 服务器名称

默认名称为 **AI Emby**，网页标题和播放器读取的服务器信息使用同一名称。可在「系统设置 → 基础设置 → 显示与检索」修改服务器名称，保存后生效。部分播放器缓存服务器名称，需要刷新服务器信息或重新连接。
