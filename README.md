# AI Emby

AI Emby 是一款电影、剧集与 STRM 媒体库管理服务。在一个面板里完成媒体浏览、文件管理、扫库和元数据刮削，适合管理本地磁盘、NAS 或挂载目录中的影视资源。

## 主要功能

- **媒体库管理**：管理电影与剧集，支持全量扫描、刷新扫描、定时扫描和媒体库排序。
- **并发扫库**：同时处理多个媒体库，也可调整单个媒体库内的文件扫描并发。
- **元数据刮削**：通过 TMDB 获取 NFO、海报、背景图和剧集缩略图，支持选择目录、磁盘及刮削并发。
- **自动处理**：监控媒体目录变化，按设置自动刮削或刷新本地元数据。
- **文件与账号管理**：浏览媒体目录，管理用户、播放权限和 API 密钥。
- **日常使用**：浅蓝白管理面板、明暗主题切换、当前设备保持登录，并提供字幕增强、片头片尾和 Telegram 通知等设置。

## 安装

### 环境要求

- Linux x86_64（amd64）。
- 已安装 Docker、Docker Compose 和 Git。
- 可访问的媒体目录；需要写入 NFO 和图片时，该目录应可写。

数据库由 Docker Compose 一并启动，无需单独安装 PostgreSQL。

### 1. 准备部署目录

```bash
git clone https://github.com/LLL198/ai-emby.git
cd ai-emby
cp .env.example .env
mkdir -p app-data app-backups postgres-data secrets media update-control
```

### 2. 填写配置

用文本编辑器打开 `.env`，填写数据库密码、管理员初始密码和媒体目录。

| 配置项 | 用途 |
| --- | --- |
| `POSTGRES_PASSWORD` | 必填，数据库密码 |
| `ADMIN_PASSWORD` | 必填，首次创建管理员的密码，至少 12 字节；使用英文字符时至少 12 位 |
| `MEDIA_PATH` | 宿主机媒体目录，例如 `/mnt/media`；默认 `./media` |
| `HTTP_PORT` | 网页访问端口，默认 `8097` |
| `IMAGE_TAG` | 镜像版本，默认 `latest` |
| `PUID` / `PGID` | 容器运行用户和用户组，默认均为 `0`；自定义时需确保媒体与数据目录可读写 |
| `LICENSE_KEY` | 授权密钥，按所用授权方式填写 |

已有账号的密码请在面板内修改，调整 `ADMIN_PASSWORD` 不会重设已有管理员密码。

### 3. 启动服务

```bash
docker compose pull
docker compose up -d --no-build
```

浏览器打开 `http://服务器地址:8097`。如果修改了 `HTTP_PORT`，使用对应端口。

首次登录使用用户名 `admin`，密码为 `.env` 中填写的 `ADMIN_PASSWORD`。如页面提示需要授权，按提示完成授权配置。

登录后会自动记住当前设备。清除网站数据、退出登录或修改密码后，需要重新登录。

## 添加媒体库

1. 打开管理面板的「媒体库管理」，选择「新建媒体库」。
2. 填写名称，选择电影或剧集类型。
3. 选择容器内的媒体目录，保存并查看扫描进度。

`MEDIA_PATH` 指向的宿主机目录在容器里显示为 `/media`。例如，宿主机 `/mnt/media/电影` 对应面板中的 `/media/电影`。

电影和剧集建议分别建库，剧集按季整理。可参考以下命名：

```text
/media
├── 电影
│   └── 电影名称 (2024)
│       └── 电影名称 (2024).strm
└── 剧集
    └── 剧集名称 (2024)
        └── Season 01
            ├── 剧集名称.S01E01.strm
            └── 剧集名称.S01E02.strm
```

剧集文件名保留 `S01E01` 这样的季集编号，有助于识别具体集数。存在同名作品时，可在作品目录名中加入正确的 `{tmdb-编号}`，例如 `电影名称 (2024) {tmdb-12345}`；示例编号需替换为实际作品的 TMDB ID。

## 扫库与刷新

在媒体库菜单中选择「全量扫描」或「刷新扫描」，也可以使用「刷新全部媒体库」。任务进度与失败原因可在「实时日志」中查看，运行中的任务支持暂停和继续。

「扫描与定时设置」中可以调整：

| 设置 | 作用 | 范围 |
| --- | --- | --- |
| 同时扫描上限 | 同时进行全量扫描的媒体库数量 | 1–64 |
| 同时更新上限 | 同时进行刷新扫描的媒体库数量 | 1–64 |
| 单库扫描并发 | 单个媒体库内同时处理的文件数量 | 1–32，默认 8 |

并发设置对新任务生效。机械硬盘、网络挂载或繁忙的 NAS 建议逐步增加并发，结合实际速度与磁盘负载调整。

需要自动扫库时，可设置每日、每周或按分钟间隔执行。面板中的定时时间使用 UTC。

## 元数据刮削

扫库负责把媒体加入影库；刮削负责获取作品信息，并将所选 NFO 和图片写入媒体目录。

### 配置 TMDB

打开「TMDB 管理」，填写 `API Key / Read Access Token`，确认 API 基础地址与请求频率，然后保存。通过代理访问时，在「代理设置」中启用相应范围。

需要浏览时自动获取信息，可开启「启用 TMDB 按需元数据」。

### 手动刮削

1. 打开「刮削管理」，开启「启用刮削」。在「刮削配置」中启用 TMDB，点击「配置刮削内容」选择电影、剧集、季和单集需要下载的内容。
2. 设置覆盖策略：可跳过已有文件，也可覆盖已有文件；中文元数据、中文海报和 Fanart.tv 按需配置。
3. 在「实时监控」中关闭监控，再进入「手动任务」开启手动刮削。
4. 点击「选择目录 / 磁盘」，勾选本次处理的范围。
5. 点击「刮削并发」，设置同时处理的媒体数量，支持 **1–32**。
6. 点击「扫描任务」，查看待刮削、跳过和覆盖的文件，再点击「开始刮削」。

修改范围、并发或刮削配置后，需要重新扫描生成任务计划。刮削并发与 TMDB 请求频率分别设置，提高并发仍会受到 API 请求频率限制。

刮削过程中可查看逐项日志，暂停、继续或停止任务。失败记录会显示具体媒体、目标文件和原因，修正后可重新选择相关目录刮削。

### 实时监控

在「刮削管理 → 实时监控」选择媒体库目录并启用监控，可自动处理新增或变化的内容，也可开启「自动刷新本地元数据」。执行手动批量刮削前，先关闭实时监控。

## 系统更新

需要在面板中安装更新时，先为部署主机安装更新服务。主机需支持 systemd，并安装 Python 3.11+、curl 和 Docker Compose。

在部署目录执行一次：

```bash
sudo bash scripts/install-updater.sh "$PWD"
```

随后打开「系统设置 → 检测更新」，按页面提示安装。更新期间服务会短暂重启，完成后重新打开页面即可。

使用自定义 `PUID` / `PGID` 时，安装后确认对应容器用户能读写 `update-control` 目录。更新日志与数据库备份保存在 `app-backups/updates/`。

## 数据保存与日常维护

| 部署目录 | 内容 |
| --- | --- |
| `app-data/` | 应用数据与缓存 |
| `postgres-data/` | 数据库文件 |
| `app-backups/` | 备份与更新日志 |
| `update-control/` | 面板更新服务使用的目录 |
| `MEDIA_PATH` 指定的目录 | 媒体文件、STRM，以及刮削生成的 NFO 和图片 |

查看服务状态和日志：

```bash
docker compose ps
docker compose logs -f --tail=100
```

停止或重新启动：

```bash
docker compose stop
docker compose up -d --no-build
```

迁移已有部署时，保留 `.env`、应用数据、数据库、媒体挂载路径和授权机器标识，并沿用原来的 Compose 项目名与服务名。

## 常见问题

**面板看不到媒体目录**

检查 `MEDIA_PATH` 是否指向正确的宿主机目录，面板中选择的路径是否位于 `/media` 下，以及容器用户是否有读取权限。

**刮削识别失败**

先查看日志中的标题、年份和媒体类型，再检查媒体库类型、目录名及季集编号。同名或容易混淆的作品可以补充正确的 TMDB ID。

**NFO 或图片写入失败**

检查媒体挂载是否可写、容器用户是否有写入权限，以及网络挂载或云盘文件系统是否支持所需写入操作。具体错误路径以日志为准。

**提高并发后仍然很慢**

查看磁盘、网络与 TMDB 请求频率。多个并发设置会共同影响负载，可先减小任务范围，再逐步调整。

**面板检测到更新，但无法安装**

确认宿主机更新服务已安装并运行，容器能读写 `update-control`，再查看面板提示及 `app-backups/updates/` 中的更新日志。
