# 运行结构

公开端口 8097 由 `scraper-gateway` 提供。原程序在 18097 端口，重建服务在 loopback 18098 端口。网关保留原程序认证与授权检查。

- 手动刮削：1–32 个媒体对象并发，TMDB 请求共享限速器；单任务没有原先五分钟的整体超时。
- 手动扫库、刷新：单库默认 8 个文件处理任务，可选 1–32；媒体库之间默认 2 个扫描任务和 2 个更新任务。
- 单库一次遍历生成清单，批量查询、批量写库，父级 Series/Season 去重。
- 扫描使用 `FOR NO KEY UPDATE` 与原程序协调。取消或失败时不提交新快照、不执行删除清理。
- 原程序的定时扫描、内部监控仍由原程序执行；它们尚未全面接入新扫描池。
- 实时刮削监控仍由原程序负责；开启原监控时禁止启动重建服务的手动刮削，以防重叠。
- 长期登录仅延长当前设备已有有效会话；退出、改密码和删除账户仍能使会话失效。
- `/System/Updates` 和 `/System/Updates/Status` 由网关处理，更新源固定为 `LLL198/ai-emby`。

宿主机更新服务从共享目录取任务，下载正式 Release 包，校验清单、SHA256、包内路径与版本，基于当前运行镜像构建新镜像，保留运行依赖与全部挂载。数据库备份用于恢复参考，不会在回滚时自动覆盖数据库。
