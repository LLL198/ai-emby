# 运行结构

公开端口 8097 由 `ai-emby-gateway` 提供。核心服务在 18097 端口，扫描刮削服务在 loopback 18098 端口。网关保留用户登录验证和管理员权限检查。

- 手动刮削：1–32 个媒体对象并发，TMDB 请求共享限速器；单任务没有五分钟的整体超时。
- 手动扫库、刷新：单库默认 8 个文件处理任务，可选 1–32；媒体库之间默认 2 个扫描任务和 2 个更新任务。
- 单库一次遍历生成清单，批量查询、批量写库，父级 Series/Season 去重。
- 扫描使用 `FOR NO KEY UPDATE` 与核心服务协调。取消或失败时不提交新快照、不执行删除清理。
- 核心服务的定时扫描、内部监控仍由核心服务执行；它们尚未全面接入新扫描池。
- 实时刮削监控仍由核心服务负责；开启实时监控时禁止启动扫描刮削服务的手动刮削，以防重叠。
- 长期登录仅延长当前设备已有有效会话；退出、改密码和删除账户仍能使会话失效。
- `/System/Updates` 和 `/System/Updates/Status` 由网关处理，更新源固定为 `LLL198/ai-emby`。

宿主机更新服务从共享目录取任务，下载正式 Release 包，校验清单、SHA256、包内路径与版本，基于当前运行镜像构建新镜像，保留运行依赖与全部挂载。数据库备份用于恢复参考，不会在回滚时自动覆盖数据库。

核心服务和扫描刮削服务均从 `companion` 源码编译，通过运行模式区分职责；网关从 `gateway` 源码编译。Docker 构建和 Release 打包使用同一套源码，Release 清单记录版本、源码提交及运行文件的 SHA256，供更新时校验。
