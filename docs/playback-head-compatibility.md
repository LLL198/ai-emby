# STRM 播放的 HEAD 兼容

部分播放器会先用 HEAD 获取视频大小，再发起 GET 播放。网盘返回的播放链接可能接受 GET，却拒绝 HEAD，导致播放器在正式读取视频之前报错。

2026-10-02 对当前媒体库的一部电影和一集电视剧进行抽查：源服务返回 302；沿跳转链发起 HEAD 时，最终网盘返回 403；使用 GET 和 `Range: bytes=0-1023` 时，最终网盘返回 206，并成功读取 1024 字节。浏览器和 mpv 的两种 User-Agent 结果一致。这能证明一类 HEAD 兼容问题，不能替代反馈用户的客户端复现。

## 处理方式

- 只处理已入库 STRM 的 HEAD 播放请求，覆盖普通和快速播放路由。
- 先通过核心服务原来的 HEAD 请求检查登录、媒体权限和设备限制。
- 鉴权成功且返回重定向后，用原客户端 User-Agent 和 `Range: bytes=0-0` 获取源文件信息，最多跟随五次跳转，总等待不超过八秒。
- 从 Content-Range 还原完整文件大小，向播放器返回没有正文的 HEAD 200 响应。源站、网盘不接收面板的登录头和 Cookie。
- 解析失败、源站拒绝访问、返回错误页面或跳转过多时，保留原响应。
- GET 播放继续由核心服务返回 302，视频播放流量仍由客户端直接读取。实际本地文件和转码播放不经过该处理。

HEAD 兼容成功的响应包含 `X-AI-Emby-Head-Compatibility: range-get`，可用于排查客户端请求。

## 验证

网关测试覆盖 GET 签名源拒绝 HEAD、签名参数原样保留、登录信息不转发、未授权请求不访问源站、相对跳转、无效长度、错误页面、跳转循环和普通播放路由。使用同一兼容处理函数对上述两个真实源进行验证，HEAD 均返回 200、正确的文件大小及空正文；核心鉴权通过受控服务测试验证。
