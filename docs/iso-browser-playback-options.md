# ISO 网页播放：成熟方案与当前链路的差距

调研与验证日期：2026-10-07。已实现 HLS 播放链路，并用远程真实片源及实际本地影库进行了浏览器实播。本地服务已安装 `2026.10.07-033344`；正式更新包以 [GitHub Releases](https://github.com/LLL198/ai-emby/releases) 为准，线上站点尚未部署。

## 结论

网页主线已接入 **libbluray + FFmpeg 按需封装 + HLS + hls.js / Safari 原生 HLS**。时间索引可靠、终端编码兼容时保留视频编码；否则转成 H.264。现有按需读盘组件继续使用，浏览器取流改为完整点播时间轴上的独立片段。

这是成熟组件的组合，不是一个已经支持所有远程 ISO 的现成插件。HLS 播放库处理分段加载、缓冲与时间轴；ISO 正片选择、时间到字节位置的映射、远程 Range 和片段时间戳仍由服务端负责。

## 爆米花能借鉴什么

[网易爆米花的官方 App Store 介绍](https://apps.apple.com/cn/app/id6480252695)确认支持 ISO 原盘、自研播放内核和 Emby/Jellyfin 媒体库。该介绍没有披露具体读盘库、网络缓存或定位算法，不能将某个开源内核认定为它的实现。

可以借鉴的产品目标是：点击播放时按需读源；拖动时定位目标附近的关键帧；设备支持时保留原编码；播放会话和媒体时间轴保持连续。网页能采用相同原则，但浏览器能够解码的格式、音轨和 HDR 能力须逐设备判断。

## 三条路线

| 路线 | 可复用的组件 | 对当前项目的适用性 | 未解决的部分 |
| --- | --- | --- | --- |
| 按需封装为 HLS | libbluray、FFmpeg、hls.js、Safari 原生 HLS | 已实现并通过真实片源的 Chromium 实播；兼容现有 video 元素和控件 | Safari、移动设备、高码率及更多复杂光盘仍需验证 |
| 浏览器直接处理原编码正片 | libmedia / AVPlayer，WebCodecs、Wasm | 候选实验路线，可减少服务端封装或音频处理 | 文档格式列表未列 ISO；仍需读盘桥接；4K HEVC 性能、字幕、移动端和时间定位需实测 |
| 原生客户端 | 支持 ISO 的播放器，通过现有媒体库协议取源 | 可作为需要原盘能力的补充入口 | 需要安装客户端，不满足纯网页播放要求 |

[hls.js](https://github.com/video-dev/hls.js)提供 VOD、分段 MP4、TS 和缓冲播放能力；HEVC、音频格式等仍受浏览器运行时支持限制。它不会直接解析蓝光 ISO，也不会添加浏览器缺失的硬件解码能力。

[libmedia](https://github.com/zhaohappy/libmedia)提供 Matroska、MPEG-TS 等解封装，以及 WebCodecs/Wasm 解码。其格式列表不能作为完整蓝光 ISO 支持的证据；软解可作为兼容候选，不能承诺低功耗、流畅播放 4K HEVC。

[Jellyfin 的播放分类](https://jellyfin.org/docs/general/post-install/transcoding/#types-of-transcoding)可直接借鉴：原文件播放、只换封装、只转音频、转视频逐级选择。[Jellyfin 的电影格式文档](https://jellyfin.org/docs/general/server/media/movies/)同时说明 ISO 不属于受支持格式，不能把整套 Jellyfin 视为已解决远程 ISO 的替代方案。

## 实施前的差距（旧实时链路）

1. `disc-reader/reader.c` 使用 libbluray 选片和读取，旧 IPC 只提供 `READ`，定位使用 `bd_seek` 的字节接口，未接入 `bd_seek_time` 时间接口。
2. `companion/features_playback.go` 的旧实时模式中，中途定位走重新编码；视频复制限于从头播放的兼容 H.264，未提供 HEVC 原编码输出协商。
3. `frontend/web/js/feature-player.js` 拖动时删除旧任务、清空 video.src、重新 load，再等待新流；缓存内拖动也走重新建流。
4. `companion/playback_stream.go` 提供一次性响应，只有一个消费者，没有稳定的片段地址、可重试片段或全片分段时间轴。

因此，减少落盘已经改善源读取成本，但没有提供完整的点播定位机制。简单替换播放控件或只引入 hls.js 不足以解决这些问题。

## 推荐的服务端与网页分工

`远程 ISO Range → 有界源缓存 → libbluray 正片/时间定位 → 按需封装片段 → HLS → 网页设备解码`

- 打开影片建立一个播放会话，保留读盘上下文和正片信息；拖动不重新解析整张盘。
- 使用 libbluray 的时间接口定位，并返回实际起始时间和位置。接口见 [bd_seek_time](https://videolan.videolan.me/libbluray/bluray_8h.html)。返回的是定位后的字节位置，不能把调用成功等同于精确落在请求帧。
- 浏览器和服务端协商视频、音频、位深等能力。兼容时只换封装，音频不兼容时只转音频；视频不兼容才转视频。换封装本身不降低视频画质，但不能据此承诺所有 HDR、杜比或无损音轨都能在浏览器输出。
- 使用完整点播时间轴和稳定片段地址。缓存内拖动由浏览器完成；未生成区域的请求驱动后台从相邻关键帧生成片段，按需要切换 FFmpeg 工作位置。
- 片段可以放有总字节上限的内存缓存或临时内存目录，读取完成后按策略释放。不要为了零落盘牺牲标准 HTTP 重试与浏览器正常定位，也不要后台持续生成整部影片。
- hls.js 负责浏览器分段和缓冲，Safari 可使用原生 HLS。服务端仍要保证播放列表时长、关键帧边界、跨片段时间戳和取消语义正确。
- 读盘错误、缺失索引和不可靠 Range 明确返回原因；不能默默全盘下载后宣称已经实现按需播放。

[Jellyfin 的 DynamicHlsController](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/DynamicHlsController.cs)可参考片段服务和转码参数组织方式，不能直接照搬它的文件缓存、权限与会话模型到本项目。

## 验证目标

以此前测试的《我不是大师》第 14 集为主要真实样本，再配合多片段、多角度和时间索引异常的本地样本：

1. 先验证 libbluray 的时间定位结果能独立解码，正确对应目标附近的画面；比较缓存媒体时长、播放列表时长与实际视频时间。异常索引不能直接用作 HLS 时间轴。
2. 先做原编码封装到 HLS 的小范围验证，确认 HEVC 终端能够持续播放，再验证不支持终端的视频转码回退。
3. 在浏览器验证从头、25 分钟、片尾、前后反复拖动、暂停时拖动，以及断网后的片段重试。必须观测画面与声音持续推进，不能只以首批 MP4 字节或 HTTP 200 判定成功。
4. 检查上游读取位置与字节量，确认中途定位不会读取前面的整段影片；检查源缓存、片段缓存和总进程内存有界，不生成完整源镜像或完整电影输出。
5. 检查退出、快速切片和多用户并发的清理与权限；所有片段端点都要继承影片访问控制。

## 已实现的链路

- 私有读盘协议升级为 `BDR2`，新增 `SEEK`，使用 libbluray 返回的实际时间和字节位置。Go 仍兼容 `BDR1` 字节读取；旧组件或异常索引走解码定位。
- 一个根会话保留 ISO 目录、源缓存和读盘进程；浏览器只请求目标附近的片段。拖动取消片段生成，不销毁根会话。
- 每个片段使用相邻访问点之间的私有字节视图，避免 FFmpeg 在中途定位时重新扫描整部影片首尾。索引异常时保留 FFmpeg 准确定位并关闭视频复制。
- 播放列表包含完整 VOD 时间轴、独立初始化片段和稳定片段地址；每个片段以 discontinuity 表达独立编码时间戳，由 hls.js 处理浏览器缓冲和时间衔接。
- 本地固定版本 hls.js 1.7.3，附 Apache 2.0 许可，不依赖外部 CDN。检测 HEVC / HEVC 10-bit 的 MSE 能力；不兼容时输出 H.264，音频统一为 AAC。播放设置中的“转码播放”可强制选择 H.264。
- HLS 路径不自动全盘下载。准备失败会显示原因；用户可以点击“转码播放”尝试旧兼容路径，完整缓存状态会明确显示。
- 片段输出上限 16 MiB，片段缓存总上限 32 MiB，旧源块缓存另有 8 MiB 上限。这些是各缓冲的上限，不能当作 FFmpeg、读盘库及整个进程的总内存上限；超过片段上限会报错，需使用转码模式。
- 列表、初始化片段和媒体片段均检查用户、影片和播放权限；断开单个请求不关闭根会话，退出或删除任务会清理进程及内存片段。

主要实现：`companion/playback_hls.go`、`companion/media_iso_bluray.go`、`disc-reader/reader.c`、`frontend/web/js/feature-hls.js` 与 `feature-player.js`。原实时流和缓存文件接口继续保留。

## 真实片源验证记录

样本：《我不是大师》第 14 集，远程原生 ISO，1,995,309,056 字节；正片 3186.56 秒（53:06.56），HEVC Main 8-bit、3840×1920、25 fps，AAC 双声道。测试使用线上已授权片源和本地隔离的播放服务，观看进度写入本地模拟接口。

| 项目 | 实测结果 |
| --- | --- |
| 准备时间 | 约 5.03 秒，建立 747 个片段，初始上游读取约 15.69 MiB |
| 25 分钟目标片段 | 从 1497.795 秒的访问点生成，片段跨度 3.840 秒；生成、取回及首帧解码检查合计约 1.89 秒，新读取上游 4 MiB |
| 后续目标片段 | 1504 秒目标约 1.82 秒，1512 秒目标约 2.19 秒；各新增上游读取 4 MiB |
| 原编码浏览器实播 | 3840 宽度画面正常，播放时间连续跨越多个片段；拖到 25 分钟后继续播放，MediaSource 地址保持不变 |
| 暂停时快速拖动 | 1800 → 40 → 1510 秒，最终停在 25:10，保持暂停且画面可用，播放会话保持不变 |
| H.264 兼容模式 | 1920 宽度画面正常；拖到 25 分钟后持续跨片段播放约 80 秒，MediaSource 地址保持不变 |
| 片尾 | 从 3178 秒播放至“播放完毕”，显示 53:06 / 53:06，停止进度回传精确限制在 3186.56 秒 |
| 下载与落盘 | 测试禁止完整源 GET；真实片段验证未生成 `source.iso` 或 `video.mp4` |

表中秒数是当次本地环境的测量，不是所有设备的首播或拖动延迟保证。浏览器实播验证了画面和时间推进；未进行人工听音、完整 53 分钟观看或逐帧音画同步测量。

片尾的最后访问点仍声明音轨，但没有实际音频包。实现先检查最后三个区间的包数，仅在选定音轨确实没有包时补静音 AAC，避免 FFmpeg 因缺少有效音频参数失败。浏览器按已知片尾裁剪编码延迟，播放器也限制进度上限。

自动化覆盖：分段 MP4 完整性与内存上限、异步会话、随机片段、重试结果一致、HEAD 不生成视频、其他用户无法访问片段、取消请求保留会话、删除任务；同时回归原有 ISO、伪装 ISO、DVD、多角度默认角度、暂停/停止及实时输出路径。

人工测试盘的实际视频为 12 秒，但 libbluray 标题时长约 624 秒。实现拒绝将该异常导航索引用作 HLS 时间轴，使用 12 秒准确解码时间轴；测试另外验证失败的 `SEEK` 后仍能正常 `READ`。

## 实际本地部署与拖动回归

本地地址 `http://127.0.0.1:28097` 原来仍运行 `2026.10.06-003355`，未包含新的 HLS 播放链路。更新前保存了数据库转储和两份部署配置；更新后媒体条目 2715、媒体库 3、账号 1，数量与更新前一致。回滚资料保存在工作区外的 `deployment-backups/hls-local-2026.10.07-024028`。

实际影库《我不是大师》第 14 集的测试同时发现快速拖动中的请求竞态：旧初始化片段的取消回调会取消新目标的媒体请求。调用栈落在 hls.js 的 `loadInitSegmentIfNeeded` 错误回调。HLS 拖动现在先调用公开的 `stopLoad()` 停止初始化和媒体加载，让取消回调在停止状态下完成，再在下一轮事件循环以最后选中的位置调用 `startLoad()`。已缓冲位置也经过同一调度入口，防止连续拖动回缓存时仍有旧目标待执行。整个过程保留 MediaSource、已有浏览器缓冲、服务端根会话和源缓存；退出时取消待执行的重启。

修复后验证了暂停时的 `1800 → 40 → 1510` 秒及 `40 → 1800 → 600 → 2750 → 1500` 秒快速拖动，最终画面可用、保持暂停且 MediaSource 地址不变。另用鼠标将进度条从约 25 分钟实际拖到 14:59，随后正常跨多个片段播放至 15:36；画面宽度 3840。修复同时写入本地容器镜像和内嵌网页，避免只改运行中的网页文件而在重启后丢失。

Safari 原生 HLS、移动端、HEVC 10-bit/HDR 的广泛兼容性、复杂多片段 HLS、高码率原盘、网络中断恢复及多用户长时间负载尚未充分实测。当前结果证明推荐路线可行，并不表示所有 ISO 都已达到 MKV 或原生播放器的体验。
